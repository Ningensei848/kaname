# チャットが不適切なUIである理由とキャンバスの活用

> [!warning] 要約対象の制限
> 入力上限により、変換後の本文の先頭20,000文字だけを要約しています。
> 記事後半の論点が含まれない場合があります。記事全体の確認には出典URLを参照してください。

> [!abstract] AI要約
> AIの普及から3年が経過し、大規模言語モデル（LLM）との主なインタフェースはいまだにチャットが主流となっている。しかし、スティーブン・ピンカー氏の指摘するように、チャットは万能な汎用解である一方、特定のタスクを遂行する際には必ずしも最適なUIとは限らない。ユーザーが明確な目的を持っている場合、その場に応じて生成・カスタマイズできるUIが求められる。GitHub Copilotアプリでは、この課題に対する解決策として「キャンバス」と呼ばれる機能が提供されている。キャンバスはブラウザのクロームなしで動作するフルスタックアプリケーションであり、GitHub Copilotエージェントと双方向に通信し、通常のプログラムと同等の柔軟な操作を可能にする。例えば、Connect 4のようなゲームをAIと対戦するインタラクティブな表現を通じて、チャット以外のUIが持つ可能性を示している。

## 重要ポイント

- AIとの対話において、チャットは初期から普及した汎用的なUIである一方、タスク指向の作業では不適切な場合がある。
- GitHub Copilotアプリで導入されている「キャンバス」は、特定の目的に合わせて動的に生成されるカスタマイズ可能なUIである。
- キャンバスはブラウザの枠組みを持たないフルスタックアプリであり、AIエージェントとサーバー間で双方向の通信を行える。
