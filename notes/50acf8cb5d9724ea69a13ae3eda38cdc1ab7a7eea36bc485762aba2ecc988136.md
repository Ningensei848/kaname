# コードを読むべきか、RAGは死んだのか、SkillsはMCPを殺したのか

> [!abstract] AI要約
> GitHub Podcastの最新エピソードに基づき、AIに関する様々な「ホットテイク（過激な意見）」を深く掘り下げて検証しています。AIが生成したコードを読む必要があるかという問いに対し、コードに対する責任は開発者にあり、リスクや変更の重要度に応じてレビューの深度を変えるべきであると論じています。すべてのコードに同じ注意力は不要ですが、結果を説明し所有できるまで確認するアプローチが求められます。また、AIの利用を前提とした採用市場においても、一律のツールの強制ではなく、AIの活用・不使用の判断基準やレビュー能力、エンジニアとしての判断力（ジャッジメント）が重要視されると解説しています。

## 重要ポイント

- AIが生成したコードを読む必要があるかという問いに対し、開発者は結果に対して責任を負うため、リスクに応じてレビューの深さを変えるべきであると結論づけている。
- プロダクションの認証リファクタリングとCSS実験では必要なレビュープロセスが異なるため、リスクがどこにあるかを見極めるスキルが重要である。
- 採用市場においてAIの不使用が一律に不採用の理由になるわけではないが、AIをいつ使い、いつ手動で作業すべきかを説明できる「判断力（ジャッジメント）」が強いシグナルとなる。
