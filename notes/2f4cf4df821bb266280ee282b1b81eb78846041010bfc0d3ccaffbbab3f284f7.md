# GitHub Security Lab Taskflow Agentを活用したAI駆動ファジング

> [!warning] 要約対象の制限
> 入力上限により、変換後の本文の先頭20,000文字だけを要約しています。
> 記事後半の論点が含まれない場合があります。記事全体の確認には出典URLを参照してください。

> [!abstract] AI要約
> 本記事では、GitHub Security LabのAntonio Morales氏が、LLMを活用した自律型セキュリティ自動化フレームワーク「GitHub Security Lab Taskflow Agent」をベースに開発したC/C++プロジェクト向けファジングタスクフロー（Fuzzing Taskflow）について解説しています。従来のファジングではカバレッジの維持、ハーネスの新規作成、クラッシュのトリアージなどに人間の手作業が不可欠でしたが、Fuzzing Taskflowは対象のGitHubリポジトリを指定するだけで、エントリーポイントの特定、ビルドシステムの解析、ハーネスの作成、AFL++の実行、カバレッジの確認、ハーネスの改善、クラッシュのトリアージ、脆弱性レポートの作成までを自律的に行います。実行にあたっては、LLMが選定した任意のビルドコマンドなどがホスト上で直接実行されるリスクがあるため、コンテナを使わずにGitHub Codespacesなどの使い捨て環境で特権を持たずに実行することが強く推奨されています。

## 重要ポイント

- GitHub Security Lab Taskflow Agentをベースにした自律型ファジングパイプライン「Fuzzing Taskflow」の紹介
- ターゲットのリポジトリを指定するだけで、ハーネスの作成からAFL++の実行、クラッシュのトリアージ、脆弱性レポート作成までを自動化
- LLMが任意のビルドコマンド等をホスト上で直接実行するため、実行にはGitHub Codespacesなどの使い捨ての隔離環境が必須
